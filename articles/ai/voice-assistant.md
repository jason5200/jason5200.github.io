## 一、车载语音助手的完整链路

车载语音助手是大模型上车最典型的场景。一条完整的语音交互，经过**五段链路**：

```
用户说话
   │
   ▼
① ASR（语音识别）      语音 → 文字
   │
   ▼
② NLU（意图理解）      文字 → 意图/槽位
   │
   ▼
③ 业务处理            执行动作（开空调/导航/查询）
   │
   ▼
④ NLG / LLM（生成回复） 结果 → 自然语言
   │
   ▼
⑤ TTS（语音合成）      文字 → 语音
   │
   ▼
用户听到回答
```

**大模型的价值**：传统方案里 ② NLU 和 ④ NLG 是**两套独立的、需大量标注训练的模型**；大模型可以把这两步**合并成一个**——直接理解意图 + 生成回复。

## 二、各环节的技术选型

| 环节 | 传统方案 | 大模型方案 |
|------|----------|-----------|
| ASR | Kaldi、自研声学模型 | Whisper、Paraformer |
| NLU | 意图分类 + 槽位提取（规则/小模型） | LLM 直接理解 |
| 业务处理 | 规则引擎、API 调用 | Function Calling |
| NLG | 模板/检索式回复 | LLM 生成 |
| TTS | 拼接式合成 | 神经网络 TTS（如 VITS、ChatTTS） |

## 三、大模型时代的新范式：Function Calling

大模型不只是聊天，还能**调用工具**。车载场景典型流程：

```
用户："把空调调到 24 度"
   │
   ▼
LLM 理解意图，输出结构化调用：
   {
     "function": "set_hvac_temperature",
     "arguments": { "temperature": 24 }
   }
   │
   ▼
业务层调用 CarHvacManager.setTemperature(24)
   │
   ▼
返回结果 "已调到 24 度"
   │
   ▼
LLM 生成自然语言回复："好的，空调已调到 24 度"
```

**关键理解**：LLM 负责「听懂话 + 说人话」，业务层负责「干活」。两者通过 **Function Calling（工具调用）** 衔接。

## 四、一个端云协同的车载语音架构

```
┌─────────────────────────────────────────┐
│              车机端                       │
│                                          │
│  ASR（本地/云端）                         │
│     │                                    │
│     ▼                                    │
│  路由判断：简单 or 复杂？                   │
│     │                                    │
│     ├── 简单（开空调/导航）→ 端侧小模型      │
│     └── 复杂（闲聊/推理）→ 云端大模型        │
│                                          │
│  业务执行（CarService 各 Manager）          │
│     │                                    │
│     ▼                                    │
│  TTS（本地合成）                           │
└─────────────────────────────────────────┘
```

**端云协同的核心**：把「高频、低延迟要求、隐私敏感」的指令放端侧，「低频、复杂、需要强推理」的放云端。

## 五、车机语音助手的特殊要求

### 1. 唤醒词与多轮对话

- **免唤醒**：特定场景（导航中）可直接下指令。
- **多轮**：记住上下文（"附近有充电桩吗？" → "导航去最近的那个"）。

### 2. 抗噪与方言

车内环境有路噪、风噪、音乐声。ASR 需要：
- 麦克风阵列 + 波束成形（定向拾音）
- 针对车载场景的声学模型微调

### 3. 低延迟

语音交互的「体感流畅」要求端到端延迟 **< 1.5s**。这也是端侧推理的价值所在。

### 4. 安全与防误触

- 驾驶中限制某些操作（如看视频）。
- 关键指令（如开窗）需要二次确认。

## 六、落地建议

| 阶段 | 目标 | 方案 |
|------|------|------|
| MVP | 打通链路 | 云端 ASR + 云端 LLM + 本地 TTS |
| 优化 | 降延迟、保隐私 | ASR 本地化 + 端云协同路由 |
| 进阶 | 深度定制 | 车载语料微调 + 端侧 RAG |

## 七、总结

| 要点 | 结论 |
|------|------|
| 完整链路 | ASR → NLU → 业务 → NLG → TTS |
| 大模型价值 | 合并 NLU+NLG，用 Function Calling 接业务 |
| 架构 | 端云协同，简单端侧、复杂云端 |
| 车机特殊 | 唤醒词、抗噪、低延迟、安全 |
| 落地路径 | MVP 云端 → 端侧化 → 深度定制 |
