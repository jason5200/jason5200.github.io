# 大模型上车：端侧推理的可行方案

> 系列：AAOS-Guide · 05-ai-integration
> 难度：⭐⭐⭐ 进阶
> 前置知识：Android 基础、对大模型（LLM）的基本认知

---

## 一、为什么要把大模型放到车端

智能座舱是大模型最自然的落地场景之一。但「云端大模型」在车上有三个痛点：

| 痛点 | 说明 |
|------|------|
| **延迟** | 网络不稳定（隧道、山区），云端往返慢 |
| **隐私** | 车内语音、位置、习惯是敏感数据，不想上传 |
| **离线** | 车机可能长时间无网络 |

**端侧推理（On-Device Inference）** 就是让模型跑在车机本地，解决上述问题。代价是：**端侧算力远弱于云端，只能跑小模型。**

## 二、端侧推理的三种技术路线

### 路线 1：量化 + 轻量模型

把大模型「瘦身」到能在手机/车机 NPU 上跑：

- **量化**：把 FP32 权重降到 INT8 / INT4，模型体积和算力需求大幅下降。
- **轻量模型**：用 1B~8B 参数的小模型（如 Qwen、Llama、Gemma 的蒸馏版）。

```
原模型 7B FP32（约 28GB）
    │ 量化到 INT4
    ▼
7B INT4（约 4GB）→ 部分高端车机能跑
    │ 换更小模型
    ▼
1.5B INT4（约 1GB）→ 手机/车机可流畅跑
```

### 路线 2：端云协同（混合推理）

简单任务端侧处理，复杂任务上传云端：

```
用户请求
   │
   ├── 简单（开空调、查天气）→ 端侧小模型，秒回
   └── 复杂（长对话、推理）→ 云端大模型
```

**路由策略**是关键：怎么判断一个请求该走端侧还是云端。

### 路线 3：端侧 RAG（检索增强）

把知识库（用户手册、车机帮助）存本地，端侧模型检索后回答：

```
本地知识库（向量数据库）
   │
   ├── 用户提问
   ├── 检索相关文档片段
   └── 端侧模型结合片段生成回答
```

适合「车机说明书」「故障排查」这类**封闭域**问答。

## 三、端侧推理框架选型

| 框架 | 特点 | 适合场景 |
|------|------|----------|
| **MediaPipe LLM Inference** | Google 出品，Android 友好 | 对话、摘要 |
| **MNN / NCNN** | 阿里/腾讯，轻量、性能好 | 通用推理 |
| **ONNX Runtime Mobile** | 跨平台，生态广 | 模型格式统一 |
| **llama.cpp** | 专注 LLM，量化好 | 跑 Llama 系模型 |

**选型建议**：
- 快速验证 → MediaPipe LLM Inference（API 简单）
- 追求极致性能 → MNN / NCNN
- 需要跑 Llama 系 → llama.cpp（Android 版 llama.rn）

## 四、一个最小可行的端侧 LLM Demo

以 MediaPipe 为例，核心代码骨架：

```kotlin
// 1. 初始化
val options = LlmInferenceOptions.builder()
    .setModelPath("/data/local/tmp/model.bin")  // 量化后的模型
    .setMaxTokens(512)
    .setTemperature(0.7f)
    .build()
val llm = LlmInference.createFromOptions(context, options)

// 2. 推理（异步）
val response = llm.generateResponse("帮我查一下明天天气")
// 3. 流式输出（对话场景）
llm.generateResponseAsync("导航到最近的充电桩") { partial ->
    // 逐 token 回调
    textView.append(partial)
}
```

> ⚠️ 关键前提：模型文件（.bin / .onnx）要先量化并打包或下载到设备。模型体积是端侧部署的第一约束。

## 五、车机场景的落地建议

### 1. 语音助手增强

- 端侧小模型做**意图识别**（开空调、导航、放音乐），快且离线可用。
- 复杂对话再上云。

### 2. 车机说明书问答（RAG）

- 把用户手册向量化存本地。
- 用户问「怎么开自适应巡航」，端侧检索 + 生成回答。

### 3. 个性化推荐

- 端侧模型学习用户习惯（常去地点、音乐偏好），做本地推荐。

## 六、工程挑战与对策

| 挑战 | 对策 |
|------|------|
| 模型太大 | 量化 + 蒸馏 + 小模型 |
| 推理慢 | 用 NPU/DSP 加速，减少 token 数 |
| 内存不足 | 模型常驻内存，控制并发 |
| 发热/耗电 | 限制推理频率，端云协同 |
| 效果差 | 针对车载语料微调 / RAG 增强 |

## 七、总结

| 要点 | 结论 |
|------|------|
| 为什么端侧 | 低延迟、隐私、离线可用 |
| 三条路线 | 量化轻量 / 端云协同 / 端侧 RAG |
| 框架 | MediaPipe / MNN / NCNN / llama.cpp |
| 车机场景 | 语音意图、说明书问答、个性化 |
| 核心约束 | 模型体积、算力、功耗 |
